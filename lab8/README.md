# Лабораторная работа № 9. Многопоточность в Java

## Цель работы

Освоить создание потоков, взаимодействие производителя и потребителей через `wait()` / `notifyAll()` и выполнение задач с помощью пула потоков `ExecutorService`. В работе используется JDK 25 LTS.

## Задания

### Общие требования

- Используйте осмысленные имена классов и методов, структурируйте код по задачам.
- Для запуска отдельных потоков вызывайте `start()`, а не `run()` напрямую.
- Для сборки рекомендуется Maven или Gradle.

### № 1. Создание потоков (2 балла)

**Задача:** создать два потока.

* Первый поток должен быть **подклассом `java.lang.Thread`**.
* Второй поток должен быть создан на основе **`Runnable`** (через отдельный класс или лямбда-выражение).

У каждого потока должен быть метод `run()`.

* Первый поток выводит 5 **чётных** чисел.
* Второй поток выводит 5 **нечётных** чисел.
* Потоки должны выполняться **асинхронно**, с вызовом `start()` для каждого из них последовательно.

**Пример:**

```java
Thread evenThread = new EvenThread();
Thread oddThread = new Thread(new OddRunnable());

evenThread.start();
oddThread.start();
```

### № 2. Producer–Consumer: склад обуви (4 балла)

**Описание:** необходимо реализовать паттерн **Producer–Consumer** для центра обработки заказов **Shoe Warehouse Fulfillment Center**.

#### Требования

Создать как минимум три типа:

1. **Order** — заказ, содержащий:

   * идентификатор заказа;
   * тип обуви;
   * количество.

   Можно использовать `record` для описания структуры.

2. **ShoeWarehouse** — склад, содержащий:

   * список типов товаров (публичное статическое поле);
   * приватный список заказов;
   * методы `receiveOrder()` и `fulfillOrder()`.

3. **Main** — главный исполняемый класс.

Вместимость очереди выберите самостоятельно.

#### Поведение

* `receiveOrder()` вызывается потоком **Producer**. Он добавляет заказы в очередь и вызывает `wait()`, если очередь заполнена.
* `fulfillOrder()` вызывается потоком **Consumer**. Он извлекает заказы из очереди и вызывает `wait()`, если очередь пуста.
* После каждой модификации очереди вызывается `notifyAll()`.

Вызывайте `wait()` и `notifyAll()` при удержании монитора одного и того же объекта, например внутри соответствующего блока `synchronized`. Проверяйте условие ожидания в цикле `while`: после пробуждения его нужно проверить повторно.

#### Потоки

* Поток **Producer** генерирует *n* заказов и вызывает `receiveOrder()`.
* Потоки **Consumer** обрабатывают заказы (по 5 заказов на поток).
* Используйте FIFO-подход.

Согласуйте число заказов и потребителей: для сценария, где каждый потребитель обрабатывает 5 заказов, выберите *n*, кратное 5, и соответствующее число потребителей.

**Пример:**

```java
Order order = new Order(1, "Nike", 10);
warehouse.receiveOrder(order);
```

### № 3. ExecutorService (3 балла)

**Задача:** модифицировать реализацию из задачи №2, применив **ExecutorService** вместо ручного управления потоками.

#### Требования

* Использовать один из пулов потоков:

  * `Executors.newSingleThreadExecutor()`;
  * `Executors.newFixedThreadPool(...)`;
  * `Executors.newCachedThreadPool()`.
* Добавить `ExecutorService` в метод `main` для отправки заказов на склад.
* Добавить `ExecutorService` в класс `ShoeWarehouse` для обработки заказов.
* Реализовать выполнение *n* заказов с использованием пула потоков.
* После обработки заказов завершить работу используемых `ExecutorService`.

#### Пример:

```java
ExecutorService executor = Executors.newFixedThreadPool(4);
executor.submit(() -> warehouse.receiveOrder(order));
executor.submit(() -> warehouse.fulfillOrder());
executor.shutdown();
```

Это фрагмент использования API, а не полная реализация задания с двумя пулами. `shutdown()` прекращает приём новых задач, но не ожидает завершения уже отправленных. Организуйте ожидание и завершение работы пулов. Не допускайте ситуации, когда все рабочие потоки ждут изменения очереди, а задачи, которые могут её изменить, не получают поток для выполнения.
